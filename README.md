# MoldExpress

Учебный прототип локального маркетплейса товаров от продавцов из Молдовы. В этой версии используются демонстрационные товары: настоящие заказы, оплата и доставка не подключены.

## Запуск

Требуется Node.js 20 или новее.

```bash
npm install
npm run dev
```

Vite напечатает локальный адрес. Для production-сборки запустите `npm run build`, результат появится в `dist/`.

## Структура товара

Общий контракт находится рядом с тестовыми данными в `src/data/products.js`. Используйте эти поля во всех частях приложения:

| Поле | Тип | Назначение |
| --- | --- | --- |
| `id` | `string` | Уникальный стабильный идентификатор |
| `name` | `string` | Название товара |
| `description` | `string` | Краткое описание |
| `priceMDL` | `number` | Цена в молдавских леях |
| `category` | `string` | Слаг категории (`home`, `food`, `clothing`, `accessories`) |
| `image` | `string` | URL изображения |
| `sellerName` | `string` | Имя или название продавца |
| `sellerCity` | `string` | Город или населённый пункт продавца |
| `rating` | `number` | Демонстрационный рейтинг от 0 до 5 |
| `reviewCount` | `number` | Демонстрационное количество отзывов |
| `badge` | `string` | Необязательная короткая метка на карточке |
| `shortSpec` | `string` | Необязательная строка основных характеристик |
| `oldPriceMDL` | `number \| null` | Необязательная прежняя цена в MDL |

Не переименовывайте поля без согласования: каталог, форма продавца и корзина используют один контракт. Основная точка интеграции интерфейса — `src/App.jsx`, стили — `src/styles.css`.

## Возможности и ограничения демо

- Поиск, категория, диапазон цены, продавец, город и сортировка сохраняются в параметрах URL.
- Язык, корзина, избранное и сравнение сохраняются в браузере. Товары, добавленные через демо-профиль продавца, существуют только в текущем сеансе.
- Остатки, варианты, условия доставки и возврата в данных не заданы; интерфейс не обещает их и предлагает уточнить наличие у продавца.
- Форма оформления работает только локально и не создаёт заказ. Для реальных заказов нужны серверный каталог и остатки, API заказов, интеграция платежей, а также подтверждённые продавцами правила доставки и возврата.

## Совместная работа

Каждый участник создаёт ветку от актуального `main`, работает в своей части, затем открывает Pull Request. Не отправляйте изменения напрямую в `main`. Перед началом синхронизируйте названия файлов и структуру товара с ответственным за интеграцию.
